# Security Policy

## Supported versions

Security fixes are applied to the latest release on the default branch (`main` / `master`) and the most recent `v*` tag when feasible.

| Version | Supported |
|---------|-----------|
| Latest `v*` release | Yes |
| Older releases | Best-effort; please upgrade |

## Reporting a vulnerability

**Please do not open a public GitHub Issue for security vulnerabilities.**

Prefer one of:

1. [GitHub Private Vulnerability Reporting](https://github.com/OmniSynth/omni-data-panel/security/advisories/new) (recommended)
2. If private reporting is unavailable, open a draft security advisory on the repository or contact the maintainers via the GitHub organization

Include:

- Affected version / commit
- Reproduction steps or proof-of-concept (non-destructive)
- Impact assessment (auth bypass, data leak, RCE, etc.)
- Whether a fix is already known

## Response expectations

- Acknowledgement within **7 days** when maintainers are available
- Coordinated disclosure: please wait for a fix or agreed public date before sharing details widely
- Credit will be given in the advisory / CHANGELOG unless you request anonymity

## Non-security bugs

Use GitHub Issues for functional bugs, documentation gaps, and feature requests. See [CONTRIBUTING.md](CONTRIBUTING.md).
